# BusyMark 0.8.0 release acceptance

Qualification date 2026-11-27. This receipt records individual gate results.
The branch requires the complete native stress workflow and the exact installed
strict Snap checks.

## Audio and speech desktop design audit

The v0.8.0 interface inventory covers Settings and its navigation, provider
and voice settings, credential and Piper actions, speech samples and narration,
audio authoring and playback, remote consent, and all entry points from the main
menu, Editor, Preview and outline. It also covers the HTML export options and
the shared toast path. Exported HTML uses the browser's standard audio element.

Speech and audio modals use the shared desktop route and dialog shell. Setting
rows, fields, progress and errors use the grouped BusyMark controls. Playback
uses compact buttons, a shared range control and the native popup selector.
The previous audio and speech behavior stays covered by the functional tests.
A narrow Wayland capture also exposed a native menu clipped at the window edge.
BusyMark now chooses the anchor using the window space on either side. GTK's
pre-popup width did not predict the mapped menu width in the Wayland trace.
Native accessibility inspection also found a missing button role on grouped
action rows. The shared row now exposes the role for actionable settings and
dialog entries, while preserving the semantic tap action and keyboard focus.
Narration progress and result playback stay above the dialog's action buttons
when the transcript scrolls. The Insert Audio dialog wraps its destination
choices and validation messages at enlarged text sizes. The playback rate
selector grows with the text to keep the selected speed visible.

The architecture audit resolves Flutter control constructors, subclasses and
dialog routes, including aliases and tear-offs. The app's shared control
implementations have explicit ownership. Older feature call sites are bounded
to their existing files, declarations and control counts. New speech and audio
screens have no legacy exceptions. The audit fixtures check these rules as
part of the Linux workflow. Widget tests exercise modal focus, localized
grouped controls, selected states and the scaled narrow layouts.

## Stream replay and transcript clipboard qualification

The corrective application retains the native ended state after GStreamer
pauses at EOF. Play opens a fresh HTTPS request for a finished non-seekable
response. The native probe feeds a real GStreamer appsrc and verifies the
production channel's EOF and PAUSED notifications. The Flutter regression
checks that one Play fetches the same URL again, feeds every byte to a new
decoder and closes the old decoder. Clipboard regressions cover standalone and
inline audio and audio within an HTML container. Relative transcript links
follow their original resources across directories while retaining their query,
fragment and HTML attribute form. Only owned audio enters the asset transaction.

Run `tools/test_audio_player_host.sh` after the official Linux build and run
`flutter test test/src/document_audio_remote_test.dart test/src/audio_asset_transaction_test.dart`.
The full branch workflow also runs the native probe. The artifact receipt and
GitHub Actions run for an exact compilation SHA provide its gate results.
Debug, profile and installed application probe failures count as FAIL.
The approved release-engine XFAIL keeps `naturalExit: false` and still requires
all of the existing conditions in [Linux engine verification](linux-engine.md).

Both verification attempts for `ac0b603afa933edc5cdace71578406c480303b25`
completed 6,055 Flutter tests and failed the first Chromium CSS check while
waiting for DevTools. Local execution passed the complete 6,056-test corpus,
including the same browser assertions. The verification job now runs the
complete browser CSS file before starting the other widget suites. Every file
runs in exactly one batch. A failure in either batch fails the job, and the
browser retains its 15-second startup deadline.
