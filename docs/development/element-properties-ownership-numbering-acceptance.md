# Element Properties: inline ownership and ordered numbering

This follow-up addresses the two correctness defects reported after the earlier
[inspector corrections](element-properties-corrections-acceptance.md). It retains
the workspace inspector, existing parser/model/transaction paths and builder
baseline **2026.08.0328**. Generated schema data and lockfiles are unchanged.
The implementation and regression coverage are committed as `5877720`.

## Corrected mappings

| Case | Verified mapping |
| --- | --- |
| Attributed link containing inline code | ``See [`{id="literal"}`](guide.md){id="reference"}`` remains a link with ID `reference`, destination `guide.md` and a code child containing the literal braces. It never becomes paragraph ID `literal`. An ordinary text edit, disk save and reparse preserve all four values. |
| Attributed inline image with attribute-like alt text | The image retains its destination, ID, width and literal alt text. A content edit serializes the opening brace with Markdown escaping and reparses to the same alt text. No paragraph ID is created. |
| Lexical attribute ownership | Only a text token emitted by the existing inline syntax, with no children and a complete matching source range, can supply attributes. Its distinct `busymark-writerside-attribute-token` identity cannot be confused with the reference serialization flag. A reference consumes the whole token. Paragraphs and standalone block suffixes use the same check. Neither internal marker reaches authored source. |
| Ordered list with authored start | An existing `start="10"` wins over the first `3.` Markdown marker during an item-property conversion. The list ID and other attributes remain authored on the list. |
| Ordered list without authored start | Conversion derives `start="3"` from the first marker. Nested lists independently derive `start="4"`, rather than inheriting the parent or losing the start. |
| Nested authored list override | The existing sibling attribute attachment runs inside list items too. A nested list with marker `4.` and `start="7"` keeps 7 during parent-item conversion, with its own ID. |
| History and persistence | One workspace property transaction creates one undo entry. Undo restores the exact original Markdown, redo restores the converted source, and Save / close / reopen retains outer and nested starts. |

The regressions reproduced the linked-code and image losses and both numbered
conversion failures before correction. Original failing output is retained in
the evidence directory. The additional nested authored override case caught a
missing nested suffix attachment; it now passes through the existing parser.

## Official contract and generated result

JetBrains documents [formatted Markdown links](https://www.jetbrains.com/help/writerside/links-and-references.html),
[inline Markdown images](https://www.jetbrains.com/help/writerside/images.html),
and [ordered/nested lists and list attribute placement](https://www.jetbrains.com/help/writerside/lists.html).
These pages establish the authoring syntax. The supported builder, rather than
an inferred rule, establishes the output assertions below.

Both property fixtures contain the actual XML serialization generated by the
production controller for starts 10/4, 3/4 and 10/7. Regression assertions compare
the generated bytes to those fixtures. Their native Markdown counterparts are
also built. The HTML verifier checks each `ol@start`, including the nested list,
and the formatted code descendant inside the attributed link.

The pinned builder renders unescaped attribute-like image alt text as its
filename fallback (`Logo`). BusyMark's existing ordinary-edit serializer escapes
the opening brace; the builder then emits the literal `{id="image-literal"}`
alt text with the reference ID and width 24. The final fixture uses those actual
saved bytes. This observation does not change the image property's semantics
or the supported baseline. The initial unescaped result is retained separately.
